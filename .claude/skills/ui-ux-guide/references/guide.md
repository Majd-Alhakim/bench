# UI/UX Reference Guide

Compiled from the public posts of @startuxdesign on Instagram. Wording is paraphrased. Brand examples come from the posts.

Coverage: 22 posts, from November 2024 to October 2026. Two posts in the first batch (a course ad and a career post) had no design content and are skipped. The last slide of most carousels is a course promo and is skipped.

## 1. UX Laws

UX laws describe how people behave on screens. Use them to explain your decisions instead of copying what looks good.

### Peak-end Rule
- People judge an experience by its best moment and its ending.
- Give users one clear highlight and a smooth finish.
- Examples: Uber shows pickup time right away to cut cancellations. Calorie apps send an end-of-day reminder to build a habit.

### Miller's Law
- The average person holds about 7 items in short-term memory.
- Reduce choices. Break information into small chunks.
- Examples: Netflix and Etsy cap categories at about 6 per row.

### Hick's Law
- More choices mean slower decisions. Fewer choices mean faster action.
- Examples: Spotify keeps its tabs minimal. Netflix highlights trending titles to guide you.

### Fitts's Law
- A bigger target that sits closer to the user is easier to tap.
- Make key actions large and reachable.
- Examples: Gmail's Compose button and Medium's Clap button.

### Law of Similarity
- People group elements that look alike.
- Use the same color, shape, or style for elements that belong together.
- Example: Apps give all primary call-to-action buttons one color so they stand out.

### Framing Effect
- The way you present information shapes how people react.
- Positive framing drives more action than negative framing.
- Examples: Navan shows free cancellation up to 24 hours before booking. Zomato shows how much you saved on an order.

### Authority Bias
- Users trust verified sources and experts.
- Show badges, endorsements, and credentials where trust matters.
- Examples: Amazon's Choice badge, ZocDoc's Patient's Choice badge, Practo's years-of-experience line.

### Variable Reward
- Unpredictable rewards hold attention better than predictable ones.
- Add a controlled element of surprise to key actions.
- Examples: A spin-the-wheel discount in CalAI. A scratch card after a Zomato order.

### Occam's Razor
- If two designs solve the same problem, pick the simpler one.
- Fewer moving parts mean fewer failure points.
- Examples: Pinterest uses three tabs. Duolingo uses one daily goal and one XP number.

### Peak-Load Effect (as named in the post)
- The worst moment in a flow defines how users feel overall.
- Fix the worst point first.
- Examples: Revolut states the exact reason a payment failed. Swiggy explains why a delivery is late.

### Other laws named on a cover slide (not explained in the carousel)
Chunking, Doherty Threshold, Loss Aversion, Jakob's Law, Parkinson's Law, Serial Positioning Effect, Law of Common Region.

## 2. User Intent

Most user behavior fits four intentions. Design around the intent, not only the look.

| Intent | Meaning |
|---|---|
| Know | The user wants to learn something |
| Go | The user wants to get somewhere |
| Do | The user wants to complete a task |
| Buy | The user wants to purchase something |

Map the primary intent of each screen before you design it.

## 3. Layouts

Every product reuses a small set of layout patterns. Learn them so you see why screens exist.

### Splash Screen
- First screen shown while the app launches.
- Reinforce brand identity.
- Keep loading states clear.
- Avoid unnecessary delays.

### Timeline
- Shows events, updates, or progress in time order.
- Prioritize readability.
- Make timestamps clear.
- Highlight important milestones.

### Wishlist
- Saves products or content for later.
- Keep saved items organized.
- Surface key information.
- Encourage return visits.

### Rewards and Loyalty
- Displays points, benefits, and rewards.
- Show progress clearly.
- Highlight available rewards.
- Encourage continued engagement.

### Help and Support
- Assists users who are stuck.
- Make search and contact options obvious.
- Answer common questions first.
- Keep the language human.

### Z-Pattern (reading flow)
- Eyes move top left, then top right, then diagonally to bottom left, then to bottom right.
- Example in the post: a note-taking app's sign-up page, where the path ends on the form button.

Note: the layout post says it covers 7 patterns. Only 5 appeared in the carousel.

## 4. Color Theory for UI

### 60-30-10 Rule
- 60% neutral or base color for backgrounds.
- 30% primary color for major elements.
- 10% accent color for buttons and highlights.

### Color Hierarchy
- The brightest, boldest color draws the eye first. Muted colors recede.
- Examples: Spotify's bright green play button. Netflix's bold red Sign In button on a black screen.

### Color for Feedback
- Green means success.
- Red means error.
- Yellow or orange means warning.
- Use red for failed saves, green for confirmed saves, yellow for decisions that need attention.

### Dark Mode
- Do not just invert colors.
- Reduce contrast slightly.
- Avoid pure white text.
- Use more saturated accent colors.
- Keep brand identity across both modes.

### Color for UI States
- Active state uses the brightest shade.
- Hover uses a slightly different shade.
- Disabled elements turn gray.
- Form fields use red for errors and green for success.
- Default, hover, active, focus, and disabled should each look different.

## 5. Typography

Three posts cover typography. This section merges them.

### Terminology
| Term | Meaning |
|---|---|
| Baseline | The line the letters sit on |
| Cap height | Height of capital letters |
| X-height | Height of lowercase letters such as x |
| Ascender | Part of a letter that rises above the x-height |
| Descender | Part of a letter that drops below the baseline |
| Bar, counter, stem, loop | Parts inside a letter: the horizontal stroke, the enclosed space, the main vertical stroke, and the rounded stroke |
| Kerning | Space between two specific letters |
| Tracking | Space across a whole group of letters |
| Leading (line height) | Space between lines of text |

### Font vs Typeface
- A typeface is the whole family, such as Roboto.
- A font is one style inside it, such as bold or italic.

### Serif vs Sans-Serif
- Serif fonts feel traditional and formal.
- Sans-serif fonts feel clean and modern.
- Pick by tone and purpose, not by habit.

### Font Pairing
- Pair fonts that contrast but still fit together.
- Example in the post: Wise uses a display font for headlines and Inter for body text and buttons.
- Keep the number of fonts low.

### Alignment
- Left: clean edge, easy to read. A safe default.
- Center: formal feel. Use for short text.
- Right: adds visual interest. Use sparingly.
- Justified: gives polished edges but can create uneven gaps.
- Choose by the content, not by taste alone.

### Line Height
- 100% feels cramped.
- 120% to 150% reads well for body text.

### Line Length
- Aim for 40 to 60 characters per line.
- Longer lines tire the eye. Shorter lines break the flow.

### Kerning and Tracking
- Adjust letter spacing when pairs look too tight or too loose.
- Large headlines usually need tighter spacing. Small text needs more.

### Size and Weight
- Use size and weight to rank information.
- Keep one clear step between levels so the order is obvious.

### Hierarchy and Scale
- Build a type scale with set sizes for headings, subheadings, body, and captions.
- Apply the same scale on every screen.

## 6. Visual Weight and Hierarchy

Visual weight is how strongly an element pulls attention. Size, color, contrast, and detail drive it.

### Balance
- Symmetry feels stable.
- Asymmetry works when you plan it.
- Examples in the post: Spotify and Pinterest use uneven layouts on purpose.

### What Adds Weight
| Factor | Effect |
|---|---|
| Size | Bigger elements pull more attention |
| Color | Bright or saturated colors stand out against muted ones |
| Type | Large, bold, or uppercase text carries more weight |
| Imagery | Photos and detailed visuals outweigh plain shapes |
| Contrast | Strong difference from the background raises weight |

Give the main action the most weight. Give secondary items less.

## 7. UX Theories and Concepts

### Mental Models
- A mental model is what a user believes about how a product works.
- People lean on these models to use products more easily.

### Quantitative Research
- Uses large samples to produce measurable data.
- Answers how many, how much, and how often.

### Qualitative Research
- Explains the reasons behind the numbers.
- Example: if 30% of users delete an app after a month, qualitative research finds out why.

### Fidelity
- The level of detail in a design, whether wireframe, prototype, or final product.
- Levels: low, mid, and high.

### Affinity Mapping
- Group ideas, feedback, or data by theme using sticky notes.
- Helps you see patterns in complex information.

### Information Architecture
- The blueprint of a site or app.
- Organize and label content so users find what they need.

### Heatmaps
- Show where users click or look the most.
- Hot areas get attention. Cold areas get ignored.

### Accessibility
- Design so everyone, including people with disabilities, can use the product.
- Example: contrast between text and button color. A higher-contrast version met the stricter AAA level (above 7:1).

### Dark Patterns
- Deceptive tricks that push users into actions they did not intend.
- Example: easy sign-up with a hidden or hard cancellation path.
- These are unethical because they serve business goals over user needs.

### Wireframing

What it is:
- A wireframe is the blueprint of a screen or page.
- It shows structure and function, not visuals. Think of it as the skeleton.

Why it matters:
- Lets you visualize ideas before you design.
- Exposes usability problems early.
- Saves time because you fix structure first.

Three fidelity levels:
| Level | What it looks like |
|---|---|
| Low | Basic sketches that map ideas |
| Mid | Adds more detail to the structure |
| High | Close to the final design |

Tools: pen and paper still work. Digital options named are Figma, Adobe XD, and Balsamiq.

Tips:
- Use placeholders such as [Image] or [Button].
- Keep it grayscale so you focus on layout, not color.
- Add annotations that explain interactions.

Place in the UX process: research and understand users, create user flows, build wireframes, then test, iterate, and refine.

## 8. UI Components and Terms

| Term | Definition |
|---|---|
| Cards | Small modules that hold related information such as text, media, or buttons |
| Sidebar | A panel on the side of a page that holds navigation or content. It can hide |
| Widgets | Interactive elements such as chat windows or dashboard parts |
| Popover | A floating panel that blocks action until you click outside |
| Toggle switch | An on/off control for two opposite options |
| Text fields | Boxes where users type information |
| Modal | A pop-up that demands interaction before the user continues |
| Accordion | Stacked sections that expand and collapse to reduce clutter. Common in FAQs |
| Badge | A small counter or indicator, such as an unread count |
| Progress bar | Shows how far along a task or process is |
| Chip | A compact element that stands for an input, attribute, or action |
| Avatar | A visual stand-in for a user, such as a photo, initials, or placeholder |

### Chips
What they do: users click or tap a chip to trigger an action, filter options, or see more detail.

Four states:
- Default: unselected. Shows tags or filters.
- Hover: visual feedback when the pointer is over it.
- Selected: marks an active choice, such as an applied filter.
- Disabled: shows the chip cannot be used.

Four use cases:
1. Content filtering. Let users pick several filters at once and see the picks.
2. Tagging. Label or categorize items, such as task status on a board.
3. Marketing. Highlight a promotion or plan, such as a Popular or Save label on pricing.
4. Product attributes. Show options such as firmness so users choose with confidence.

### Avatars
Three states, based on the data you have:
- Empty: no image and no initials. Show a placeholder.
- Initials: shows the user's initials.
- User picture: the best and most personal version.

Size by context (in dp):
| Size | Where |
|---|---|
| 24 to 40 | App bars and headers |
| 40 to 48 | Lists and content blocks |
| 56 and up | Profile pages and settings |

Status and notifications:
- Green means online. Gray means offline.
- Badges show alerts or message counts.
- Action icons hint at what a click does.

Action icons:
- Add icons for editing, uploading, and similar actions.
- Place rounded buttons beside the avatar.
- Match the icon style to the result. Examples: a pencil to edit, a lock to protect, a red mark to remove.

## 9. Microcopy

Microcopy is the small text that guides users through an interface. Two posts repeat the same five examples.

- Cold error vs helpful error: a helpful message offers a next step such as Try Again or Recover Password.
- Pricing and billing: add reassurance next to money. Say what happens at the end of a trial and when you charge.
- Transparency and trust: use badges, stats, and clear fee notes near the point of action.
- Affordance: tell users what they can do, such as which file types an upload accepts.
- Status labels: name the state plainly so users know where an item stands.

## 10. Empty States

An empty state is a screen or area that has no content to show. It should explain why and what to do.

Why it matters:
- It prevents confusion at a moment when nothing is on screen.
- It turns a dead end into guidance.

Four types:
| Type | When it appears |
|---|---|
| First use | The user has not added anything yet |
| No results | A search or filter finds nothing |
| Cleared | The user finished or removed everything |
| Error | Content failed to load |

Anatomy:
1. Headline
2. Short explanation
3. Visual
4. Primary action

Common mistakes:
- Generic messages that say nothing useful.
- No next step.
- Overly cute illustrations.
- Blaming the user.

## 11. Microinteractions

Microinteractions are small, contained animations or responses triggered by a user action.

Why they matter:
- Give real-time feedback.
- Guide users through an interaction.
- Raise usability and delight.

When to use them: whenever a user clicks, swipes, types, or scrolls. Find the key actions in your UI and add a subtle animation or cue.

Four common types:
1. Loading animations. Keep users engaged during waits, show progress, and reduce perceived delay.
2. Password strength meter. Shows strength while the user types. It teaches better passwords and gives clear feedback.
3. Hover effects. Scale, shadow, or color shifts show what is interactive and guide focus. They add depth.
4. Button feedback. A small animation or color change after a tap confirms the action worked and builds trust.

## 12. UI Improvement Tips

- Put navigation where users expect it. Back and Close go on the left.
- Group related information in expandable sections.
- Place action buttons on the right. Use colored dots to draw attention to new items.
- Plan for small screens. A menu button keeps navigation tidy.
- Make tap targets bigger. About 44px suits a fingertip.
- Add personality to calls to action.

## 13. Design Judgment (Taste)

Taste is a skill. It comes from understanding why a design works.

### Core difference
- Beginners react with "this looks cool."
- Designers explain why: hierarchy guides the eye, spacing gives room, every element has a job.

### Four shifts

| Shift | Beginner | Designer |
|---|---|---|
| 1. Look to study | Scrolls Pinterest, saves 100 inspirations | Studies one design for 10 minutes, saves 5 with notes on why |
| 2. Trendy to timeless | Follows glassmorphism or bento trends | Builds on hierarchy, clarity, and spacing |
| 3. Pretty to purposeful | Adds decoration, lets AI pick the look | Removes what does not help, curates AI options |
| 4. One screen to a system | One polished screen, random fonts, inconsistent spacing | Consistent across screens with a type scale and spacing rules |

Key lines from the post: trends expire, principles do not. AI makes pretty easy, taste decides what stays.

### Practice routine
1. Pick one app or site you admire.
2. Ask why it feels right.
3. Note three specific design decisions.
4. Recreate one element in Figma.
5. Write why the original works better.
6. Build a personal reference library.

The post claims 10 minutes of active study beats 2 hours of scrolling.

### Questions to ask
When a design works:
- What do I notice first, and why that element?
- How does spacing create hierarchy?
- What breaks if I remove one thing?
- What makes this feel right compared with similar designs?

When a design feels off:
- What competes for attention?
- Where does my eye get lost?
- What one change would fix it?

## 14. Designer Mindset

| Area | Beginner brain | Designer brain |
|---|---|---|
| Core question | How do I make this look good? | How do I make this work for the user? |
| Using apps | Passive user | Notices tap targets, flows, and navigation choices |
| Starting a project | Opens Figma or AI first, picks colors, starts with the home screen | Asks who it is for, maps the journey on paper, sketches rough wireframes |
| Feedback | Takes it personally, gets defensive | Treats it as data, asks follow-up questions |
| Learning | Watches tutorials, saves inspiration | Builds something, studies one design deeply |

Habits from the post:
- Ask why before each design decision.
- Study one daily app and note three design decisions.
- Build something small every day.
- Share work and welcome honest feedback.
- Write down what you learned before you close Figma.

## 15. Quick Checklist

This list is a synthesis of the sections above, not a post.

- Does the screen match one clear user intent?
- Are choices limited and grouped in small chunks?
- Are key buttons large, close, and the same color across the app?
- Does the color hierarchy lead the eye to the main action?
- Does visual weight sit on the main action?
- Do colors follow 60-30-10?
- Do feedback colors match meaning for success, error, and warning?
- Do all UI states (default, hover, active, focus, disabled) look different?
- Is body text 40 to 60 characters wide with 120% to 150% line height?
- Do you use a limited type scale and few fonts?
- Does every empty state explain itself and offer a next step?
- Do key actions give feedback, such as a hover change or a button response?
- Do error messages offer a next step?
- Does the end of the flow feel smooth and the worst moment feel handled?
- Is the contrast accessible?
- Are tap targets about 44px or larger?
- Are type and spacing rules consistent on every screen?
- Is anything on the screen there only for decoration?
