## Change

**1. The first release becomes the Eucas companion.** It plugs into the Claude Code sessions people already run: the official unmodified CLI, the user's own login, never reading credentials. **The full team app (BRD v1.3 and PRD v0.4 as written) moves after it,** and the companion is its first slice. Claude Code only for now; Cursor next, Codex later. The rulebook is vendor-neutral (ADR-0010).

**2. Free tier:**
- **Honest safety limits:** *"Eucas never auto-approves a delete, a push to main, a send or a payment, and no rule can change that."* Absolute "never" claims about the agent itself are withdrawn (pre-mortem).
  - A **fail-closed guard** (`onFailure: "block"`) with a **heartbeat** that tells you the moment it isn't running.
  - A **mass-delete tripwire** that stops the session.
  - The limits live in managed settings with **one UAC prompt** (D-4), so neither an agent nor a repo can switch them off.
- **The rules editor** (Change 6).
- **A live token ledger and a 5-hour/weekly forecast,** read from Claude Code's status data. No credential or OAuth-endpoint reading; the user's own status line is chained, not replaced.
- **A same-file warning across sessions;** a **plain-code guided merge** (rebase, test, PR).
- **A "needs you" inbox in the tray** with Windows notifications. Calm UI; nothing opens by itself.
- **A 7-day retro** of the user's past sessions as the first run (about 4:30); never an empty first screen.
- **A one-button diagnostic.**
- **Every session is guarded.** The free limit of 3 covers session *details* only (D-1).
- **Live safety test during setup:** the first run includes a harmless blocked command to prove protection works (D-5).

**3. Pro tier: $20/month; the first 200 payers keep $15/month for life.** Shown as a **waitlist** in v0.1 (D-2).
- **Per-task budgets** with auto-pause before the plan limit.
- **The AI supervisor** (ADR-0011), working in this order:
  1. plain-code rules (v2) decide first;
  2. at Level 2 only (signals plus the trimmed last message, opt-in), a provider-hosted open model: `openai/gpt-oss-120b`, with fallbacks Gemma 4 26B and then Llama 4 Maverick (SP-SUP1);
  3. **it never approves a tool call** and **never nudges after a block**;
  4. if the model is unsure, late, invalid or out of allowance, it asks the user.

  Allowance: 10,000 model calls a month. "No, rule N forbids it" counts as answering from the rules.
- **Unlimited session details,** plus history and export.
- **Laptop-closed work (beta):** hand-off to Claude cloud routines, GitHub repos only, gated on branch protection (SP-CR1). Grows to other cloud work as each kind is proven.

**4. Server:** a thin, stateless Cloudflare Worker (ADR-0012): licence check, quota, request-schema allowlist, no content stored, OpenRouter routing with zero data retention.

**5. Licence FSL** (source visible; each version becomes Apache/MIT after 2 years). This replaces "open source (MIT) at v0.1". Payments through Lemon Squeezy or Paddle. A supporter tier (pay what you want, $10 minimum) plus GitHub Sponsors.

**6. Rules: a library plus prompted rules** (added by the client in answer to D-4):
- **A rule library:** predefined, **tested** rules the user switches on or off.
- **Prompting new rules:** the user describes a rule in plain words. Eucas drafts it as an **exact rule** (ADR-0010: exact commands, no globs or regex), shows exactly what it will allow or block, and the user confirms before it's enabled.
- Drafted rules are checked against the bypass suite and can never relax a hard limit.

This brings back the free-text rule writer that the pre-mortem had cut from v0.1, with these safeguards. Whether D-4's single UAC prompt stays as designed is confirmed with the client separately.

**7. Not in the companion's v0.1:** voice input; any phone feature (including Telegram); paid packs (sharing stays free); AI conflict resolution; the notch (CR-009's notch stays for the team app; *open:* whether the companion gets it later).

**8. Process:**
- A **landing page and waitlist on eucas.app first,** as the demand test, with "which agents do you use?". It isn't published without the client's review.
- **Only spikes before Gate 6.** Product code waits for Gate 6.
- **Anthropic's written OK before the cloud beta or a paid launch** (see Impact).
- **Kill criteria** from the pre-mortem are adopted (strategy-2026-10-26-premortem §4).

## Reason

The market scan, the competitive brief, the pre-mortem and four spikes (SP-CR1, SP-SUP1 and the earlier ones) showed:
1. The pain (babysitting several agents) is real and loud, but crowded with free tools. Anthropic absorbs the basics.
2. What nobody does: limits enforced outside the model and failing closed on Windows; user-owned rules across sessions; same-file warnings; budgets that pause work.
3. Running the supervisor on the user's own Claude plan burns their limits and is the most exposed under Anthropic's terms. A cheap open model through a provider passed every bar at Level 2.
4. A smaller first release reaches users months sooner and tests demand before the full team app.

## Impact analysis

- **Scope:** the team app scope (BRD v1.3, 52 use cases) is deferred, not deleted. Sequenced, not cut, consistent with the 14-day rule's intent, but **the 14-day "full scope" target no longer applies to v0.1.**
- **Effort and schedule:** the companion is about 28 build days plus about 5 spike days. The client accepted it and will measure actual days. Spikes run now; product code starts after Gate 6.
- **Cost:**
  - Model calls ~$0.51/month per heavy user at gpt-oss-120b prices; at most $1.48 at the full allowance.
  - Workers: cents.
  - Code signing: for an individual in Qatar, an OV certificate with a cloud signer (Azure Artifact Signing is USA/Canada-only for individuals); pending, see open questions.
  - Spikes so far: $1.75 on OpenRouter.
- **Risk:**
  - **Demand:** the waitlist test and the kill criteria.
  - **Anthropic absorbing features:** the moat is user-owned rules across sessions plus vendor neutrality.
  - **A safety incident:** honest claims, fail-closed, the heartbeat, the tripwire, the nightly canary.
  - **Terms:** the free tool adds hooks around the official CLI, which the docs explicitly allow, and the supervisor no longer uses the user's plan. The cloud beta *does* start work on the user's plan, so Anthropic's written OK is required before it ships.
  - **Provider churn:** two fallback models; ask the user otherwise.
- **Usage:** the companion uses no Claude tokens itself except the one-time setup safety test (D-5).
