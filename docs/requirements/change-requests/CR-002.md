# CR-002: Built-in Reverse Engineer and competitor teardown in every Bench project

| Requested by | Date | Status |
|---|---|---|
| Client | 2026-10-22 | **Approved: option (A)** (client: "this") |

- **Client's words:** *"make it as a built in skill inside bench that it is always done by an agent how is a reverse engineer who sets as a layer before the final BRD is done and it research the competitors and reverse engineer them"*
- **Change:**
  - Bench's project template includes a **Reverse Engineer** agent with a built-in **competitor-teardown** skill.
  - In every project's delivery flow (scenario #1), after the BA's BRD draft and **before the client approves the BRD**, the Reverse Engineer tears down the competitors and reference products named by the client (or found by its own research).
  - It produces a finding ledger, Steal/Avoid/Beat and **proposed** BRD items. The BA brings these to the client in the review session.
  - **Evidence boundary:** public evidence only. No decompiling, extracting or intercepting third-party proprietary products. REA-style deep tools are allowed only on the client's own code or permissively licensed open source.
- **Affected IDs:**
  - UC-15 (produce requirement documents: add a teardown step)
  - UC-43 (project template: add the role)
  - UC-30/UC-31 (sessions: present the teardown)
  - UC-36 (research report: the teardown is a specialized research report)
  - new BR for the evidence boundary
  - PRD block D (delivery department, Sprint 4)
- **Impact:**
  - Scope: small to medium. It reuses the research-report capability (UC-36), web search/fetch, the session engine and document generation.
  - Schedule: fits Sprint 4 (it's an agent template + skill + one flow step).
  - Usage: research costs tokens, so it runs on the Sonnet tier with a capped number of products per run (default 3).
  - Risk: low.
- **Options:**
  - (A) **Always on**: every project runs a teardown before BRD approval; the client can skip it per project. *Recommended.*
  - (B) Optional: the client switches it on per project.
- **Recommendation:** (A), plus the client's skip option.
- **Client decision (2026-10-22):** **(A) always on, skippable per project.** The BA updates the BRD; the PM updates the PRD (Sprint 4).
