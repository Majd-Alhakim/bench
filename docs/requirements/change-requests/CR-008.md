# CR-008: Drafts, not sends; no deletes on the computer; browser asks only at sign-in

| Requested by | Date | Status |
|---|---|---|
| Client | 2026-10-23 | **Approved** (client's G2 answers, [g2-answers](../interviews/2026-10-23-g2-answers.md)) |

- **Client's words:**
  - *"draft and add them to draft in email or the app that will post at only it never send or post alone"* (G2-Q6)
  - *"never delete files from computer by itself or delete a project or an app or major files"* (G2-Q5)
  - *"Only before logging in new websites"* (G2-Q3)
- **Change 1, drafts only (partly reverses CR-007):** agents **never send an email or publish a post** on their own. They write it and save it as a draft in Gmail's drafts or in the drafts of the app it would post to; the client sends it from there. Bench lists each new draft in the end-of-day digest. CR-007's "sending emails and posts as the client is automatic" and the per-agent "ask me before sending" switch are withdrawn; the **60-second send undo** in BR-90 / GR2-Q6 is withdrawn with them. Commits, pushes, PRs and merges to `main` after CI and the reviewer check stay automatic.
- **Change 2, no deletes on the computer:** an agent never deletes files, folders, projects, apps or major files by itself. Every such delete is a destructive action that needs the client (BR-58). The "scratch area" where an agent could delete freely is withdrawn. PM reading `[confirm]`: removing a file inside the agent's own git worktree as part of a code change is an edit, since git can restore it and it only reaches `main` through a reviewed merge.
- **Change 3, browser agent:** it asks only **before signing in to a website it hasn't signed in to before**. Browsing, clicks and typing are automatic. Payments, destructive actions and sends/posts in the browser follow Changes 1–2 and BR-58. This narrows CR-004's "asks before clicks, typing and new sites".
- **Affected IDs:** AS-8, BR-15, BR-58, BR-64, BR-65, BR-84, BR-86, BR-90; UC-14, UC-22, UC-37, UC-49, UC-50; glossary (Outward action, Draft-only email, Scratch area, Automatic action, Safety net, Browser agent); PRD §10 automation risk, §11, E13b ("Gmail with auto-send and undo" → "Gmail drafts").
- **Impact:** smaller blast radius: nothing irreversible leaves the machine or disappears from it without the client. Cost: the client sends every email and post by hand, and agents ask more often when a task needs a delete. Sprint 5 gets lighter (no send undo).
