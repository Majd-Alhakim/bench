# CR-004: Rich deliverables (artifacts) and computer control

| Requested by | Date | Status |
|---|---|---|
| Client | 2026-10-22 | **Approved** (decisions below) |

- **Client's words:** *"utilizing Claude artifacts like Claude docs, slides, designs, dashboards … with the ability for it to control things on the computer as grok or dots"*
- **Feasibility:** [docs/research/feasibility-artifacts-computer-use.md](../../research/feasibility-artifacts-computer-use.md) (tech lead, 2026-10-22).
  - Claude's Artifact tool is **off by default in the Agent SDK**, and publishing needs a claude.ai login.
  - Anthropic's computer-use tool needs an **API key** (not the subscription, per ADR-0002); Claude Code's computer use is macOS/Desktop-only.
  - The client's machine is **Windows 11 Home**, so there's no Windows Sandbox or Hyper-V.

## Proposed scope
| Part | MVP | v1 | Out |
|---|---|---|---|
| **Deliverables** | Agents create **docs, slides, designs and dashboards as local files**, rendered live in the agent's workspace pane (MIT/Apache renderers), exported to PDF/PPTX (+S). Effort **M** (2–3 agent-days), fits Sprint 4 | Opt-in **"Publish to Claude Docs"** (claude.ai, shareable) if spike SP-A2 passes | Turning on the Artifact tool through undocumented SDK paths. Anthropic's docx/pptx/xlsx/pdf skills are source-available, not open source, so **they're not bundled** |
| **Computer control** | **Opt-in browser per agent** (Playwright MCP, isolated profile, approval gate on clicks, typing and new-site navigation, **Take over / I'm done**, local screenshots). Effort **M** (~3 agent-days); adds ~1–2 days of risk to day 14 | **Built-in browser per agent** with a live view and full-screen Take over (Grok Bot style). Docker + WSL2 **Linux desktop per agent** only if desktop apps are needed. Effort **L** | Controlling the client's **real desktop**; Claude in Chrome on the client's personal profile; cloud VMs |

**Safety:**
- Credentials are typed only by the client during Take over.
- Outward actions remain gated (BR-15/58).
- Web content is untrusted data.
- Screenshots are stored locally with retention.
- Browser agents never run unattended in routines without explicit opt-in.

## Decisions for the client
1. Deliverables: **local files only (recommended for the MVP)**, or also publish to claude.ai (hosted by Anthropic, shareable) in v1?
2. Computer control: **browser agent in the MVP** (accept ~1–2 days of schedule risk) or **v1**?
3. Browser-only, or desktop apps too? Desktop apps need Docker Desktop + WSL2 (or Windows 11 Pro).
4. Browser autonomy default: **ask on clicks/typing/new sites (recommended)**, or allow standing rules per site?
5. The sites agents may sign in to (the client types credentials), and the screenshot retention (proposed: 30 days).

## Client decisions (2026-10-22)
1. **Browser agent in the MVP:** *"no problem I accept the delay"* (accepts ~1–2 days of risk to day 14).
2. **Browser only:** *"keep browser for know I don't have servers"* (no Docker desktop for now).
3. **Defaults** (local deliverables in the MVP, ask before clicks, typing and new sites, screenshots kept 30 days): *"ok"*.
