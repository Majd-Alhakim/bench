# CR-006: Routines can do anything the agent can do

| Requested by | Date | Status |
|---|---|---|
| Client | 2026-10-22 | **Approved** (client answer to D-UI11) |

- **Client's words:** *"yes a routine can be anything that the agent is capable of doing set with a time to be repeated"*
- **Change:** a routine is any task the agent may do, run on a schedule. CR-003 **M4** ("background and routine runs are read-only by default, enforced in code") is replaced by:
  - A routine runs with **the agent's own autonomy settings** (its preset, per-tool overrides and grants). It gains no extra powers by running unattended.
  - **Outward and reserved actions still stop and wait for the client** (BR-14, BR-15, BR-58): a routine can draft an email but never send it, can open a PR but never merge to main.
  - Each routine shows what it may do: a **Read-only** or **Can edit files** badge derived from the agent's permissions, plus the pre-run estimate (M2).
  - The 30 % weekly-headroom guard (UC-41) still defers routines.
- **Affected IDs:** UC-38 (routines), CR-003 M4, the UI routines list (direction v0.2), the SRS shell-containment NFR (M8 still applies to unattended runs).
- **Impact:** small. Removes a code-enforced restriction and reuses the per-agent permission engine. Risk: unattended writes; mitigated by M8 containment, per-turn snapshots (M10) and the trace.
