# G2 answers: open questions of PRD v0.2 §11 (2026-10-23)

The client answered the 12 "Open questions for G2". Three answers change the recommendation (Q3, Q5, Q6) and Q4 rewords it; the client accepted the rest as recommended (*"accept the rest of recommended answers"*). The changes to CR-007 are recorded in [CR-008](../change-requests/CR-008.md).

| # | Question | Client (verbatim) | Decision |
|---|---|---|---|
| G2-Q1 | Creating permanent agents/projects and deploy/release | Accepted as recommended | **Both stay with the client.** Approving a proposal or a BRD counts as an undecided decision (BR-86 kind 4) |
| G2-Q2 | 30 % target | Accepted as recommended | **Information line on the usage meter only;** it never defers work |
| G2-Q3 | When the browser agent asks | *"Only before logging in new websites"* | **The browser agent asks only before signing in to a website it hasn't signed in to before.** Browsing, clicks and typing are automatic. Payments and destructive actions in the browser still need the client (BR-58), and sends/posts stay drafts (G2-Q6) |
| G2-Q4 | Model pin | *"Models are auto picked based on the complexity the agent is going to do, and can be optionally changed"* | **Automatic by task complexity; the client can optionally change it per agent** (as recommended) |
| G2-Q5 | Scratch area / deleting | *"never delete files from computer by itself or delete a project or an app or major files"* | **Agents never delete anything on the computer by themselves:** no files, folders, projects, apps or major files. Every such delete is a destructive action for the client (BR-58). PM reading `[confirm]`: inside the agent's own git worktree, removing a file as part of a code change on its branch is an edit (git can restore it, and it only reaches `main` through a reviewed merge); deleting the worktree, the repo or anything outside it is not allowed |
| G2-Q6 | Reviewer check before sends | *"draft and add them to draft in email or the app that will post at only it never send or post alone"* | **Agents never send an email or publish a post on their own.** They write the draft and save it in the drafts of Gmail or of the app it would post to; the client sends it. This replaces "sending as the client is automatic" (CR-007) and the 60 s send undo (GR2-Q6). The reviewer-check question is moot |
| G2-Q7 | Benchmark | Accepted as recommended | 3 tasks from Bench's own backlog; Bench wins if it matches or beats on acceptance with fewer of the client's hands-on minutes; scored on acceptance, hands-on minutes, wall time, % of week |
| G2-Q8 | Day-14 installer | Accepted as recommended | Windows installer only; macOS/Linux build in CI, packaged after v0.1 |
| G2-Q9 | Demo slots | Accepted as recommended | About 1 h on days 3, 6, 9, 12 and 14, at fixed times |
| G2-Q10 | Browser agent slip | Accepted as recommended | Keep day 14; a slipped browser agent ships in v0.1.1 (about day 16). Sequenced, not cut |
| G2-Q11 | Agent full screen | Accepted as recommended | Diff, files and terminal output read-only in v0.1; interactive terminal and diff review in Phase 2 |
| G2-Q12 | Spikes now | Accepted as recommended | Run S0-1, SP-B1 and M8 now on `spike/` branches, before G6; close G0 on their results |
