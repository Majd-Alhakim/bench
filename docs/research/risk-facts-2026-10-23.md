# Research: risk facts (terms, limits, competitors, complaints)

**Date:** 2026-10-23. Builds on [anthropic-repos-and-auth.md](anthropic-repos-and-auth.md) and [ADR-0002](../adr/0002-auth-subscription-vs-api-key.md).
Labels: **[V]** checked on the primary source this session · **[S]** secondary source (news, blog, review) · **[I]** our inference. Several secondary sources about 2026 products contradict each other; where they do, both are noted.

## 1. Anthropic terms for subscription use by automation

### Facts

**(a) Pro/Max login with the Agent SDK or headless Claude Code**
- Help Center, update 2026-10-07: "You can still use the Claude Agent SDK, claude -p, and third-party apps with your subscription limits." The June 15, 2026 change (a separate, metered Agent SDK credit) was **paused**: "nothing has changed" for now. [V] https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan
- Zed's update of 2026-06-16 says the same thing: third-party apps on the Agent SDK "continue to work with Claude subscriptions exactly as they did before", and Anthropic will give advance notice before any future change. [S] https://zed.dev/blog/anthropic-subscription-changes
- Claude Code legal page: OAuth is "designed to support ordinary use of Claude Code and other native Anthropic applications". Third-party developers may not "offer Claude.ai login" or "route requests through Free, Pro, or Max plan credentials on behalf of their users", and may not "collect, store, or intermediate Claude.ai credentials or session tokens". This does not prevent "an end user from signing in to the unmodified Claude Code binary with their own Claude subscription". Enforcement can happen "without prior notice". [V] https://code.claude.com/docs/en/legal-and-compliance
- Agent SDK overview: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. Use the API key authentication…". Branding: never "Claude Code" or "Claude Code Agent", and nothing that mimics Claude Code; "{YourAgentName} Powered by Claude" is allowed. The SDK falls under the Commercial Terms. [V] https://code.claude.com/docs/en/agent-sdk/overview
- Consumer Terms (effective 2025-10-08), section 3: you may not access the Services "through automated or non-human means… Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it." No account sharing. [V] https://www.anthropic.com/legal/consumer-terms. [I] The Help Center sentence above is the "explicit permission" for SDK and `claude -p` use on a subscription.

**(b) Many agents, long-running or scheduled work**
- Legal page: "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK." [V]
- Anthropic's own **cloud scheduled tasks** (formerly "routines") run unattended on Pro/Max/Team/Enterprise, triggered by a schedule, an API call or a GitHub event. They "draw down subscription usage the same way interactive sessions do", with hard caps of 100 scheduled runs/hour/account and a minimum cron interval of 1 hour. Desktop scheduled tasks and `/loop` run locally. [V] https://code.claude.com/docs/en/routines. [I] Scheduled, unattended work on a subscription is a first-party feature, so it is not banned in itself; what's restricted is *volume* ("ordinary, individual").
- Usage Policy (effective 2026-11-12): "Agentic use cases must comply with the Usage Policy". Users are responsible for their agents' tool and browser actions. No automation for spam or account creation. Agents facing consumers must disclose that they are AI. [V] https://www.anthropic.com/legal/aup
- July 2025: weekly limits were introduced because some subscribers ran Claude Code "continuously in the background, 24/7", along with account sharing and reselling. In effect from 2025-08-28. [S] https://techcrunch.com/2025/07/28/anthropic-unveils-new-rate-limits-to-curb-claude-code-power-users/

**(c) Third-party apps wrapping Claude Code with the user's own login**
- **2026-04-04:** "third-party harnesses like OpenClaw connected to your Claude account will draw from extra usage instead of from your subscription." Boris Cherny: subscriptions "weren't built for the usage patterns of these third-party tools". A c't test measured $109.55 in tokens for one day of OpenClaw on Opus, against Anthropic's benchmark of about $6/day for an average developer. [S] https://www.infoworld.com/article/4154435/anthropic-cuts-openclaw-access-from-claude-subscriptions-offers-credits-to-ease-transition.html
- **2026-05-13:** subscriptions were reinstated for programmatic and third-party use through a metered "Agent SDK credit" (Pro $20, Max 5x $100, Max 20x $200), planned to be fully metered from June 15. [S] https://venturebeat.com/technology/anthropic-reinstates-openclaw-and-third-party-agent-usage-on-claude-subscriptions-with-a-catch
- **2026-06-15:** that change was paused (see (a)). Current status: SDK, `claude -p` and third-party apps run on normal subscription limits. [V]
- Separate program: **monthly API credits** for Max 5x ($100), Max 20x ($200) and Team (pooled, up to $500). They cover the API, Managed Agents and the **Agent SDK used with an API key from the linked Console org**, but **not Claude Code** and not extra usage. Pro is not eligible. Credits expire monthly, and requests stop at $0 unless you buy more. [V] https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers
- The legal page explicitly allows products that preinstall or run the unmodified Claude Code, provided each end user authenticates with their own subscription or key and nobody resells or intermediates usage. [V]

**(d) Rate and usage limits for Pro/Max**
- Every plan has a 5-hour session limit plus a weekly limit. Max also has a separate weekly limit for one model family. Limits are **shared across claude.ai, Claude Desktop, Claude Code and IDEs**. Extra usage ("usage credits") can be turned on, and a "wrapping up" grace lets the step in progress finish. [V] https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan
- Weekly limits were 50% higher from 2026-05-13 to 09-13. Since 2026-09-14 they are **permanently 25% above** the pre-promotion level. 5-hour limits were unaffected by the promotion. [V] https://support.claude.com/en/articles/15910845. Separately, a secondary report says the 5-hour limits were doubled on 2026-05-06. [S] https://inventivehq.com/blog/claude-code-rate-limits-explained
- Anthropic publishes **no exact token quotas and no concurrency cap** for Pro/Max. In 2025 its guidance for Max 20x was 240–480 h of Sonnet and 24–40 h of Opus per week; it also warned that running "several Claude Code instances at once" hits the limits sooner. [S] TechCrunch above.
- Incidents: quotas burned in about 19 minutes (March 2026, token-tracking bugs acknowledged); a weekly-limit bug hit about 3% of Pro/Max users, and limits were reset (2026-06-19); a runaway cascade of subagents and plugins (166 agents) emptied a weekly limit in about 15 minutes. [S] https://devops.com/claude-code-quota-limits-usage-problems/ · https://pasqualepillitteri.it/en/news/5428/claude-code-weekly-usage-limit-bug-3-percent

### Conclusion [I]
**Bench's model is allowed today for personal use.** That means the unmodified binary via the Agent SDK, the user's own `claude login`, no token handling and no shared plans. It is the case the legal page and the Help Center describe. The real risks are **volume** and **policy churn**. Anthropic moved third-party harnesses off subscriptions once (April 2026), half-reversed that (May), paused it (June), and reserves the right to enforce without notice. Bench is closer to "Agent SDK + binary" than to OpenClaw, which is why it was not singled out. But a Bench that runs heavy, around-the-clock, many-agent workloads looks exactly like the pattern Anthropic has acted against twice.

**Design constraints:**
1. **One shared budget.** The 5-hour and weekly windows are shared with the founder's own chat and Claude Code use. Read `/usage`-style rate-limit data (percent, resets_at) and show it on screen. Pause or degrade *before* the limit, not at it.
2. **Default concurrency: low.** One responder by default (already in the router). Cap parallel agent runs, for example at 2–3, configurable. Hard-cap subagent depth and fan-out, since a runaway cascade can empty a weekly limit in minutes.
3. **Opus is scarce.** Default to Haiku or Sonnet tiers. Treat Opus as opt-in per agent, with a separate meter for the model-specific weekly limit.
4. **No 24/7 polling.** Use event-driven triggers (Gmail push or watch, GitHub webhooks) and schedules at ≥1 hour granularity (mirroring Anthropic's own floor). No always-on loops, and idle agents use no tokens.
5. **Graceful stops.** Handle the "limit reached" result, queue the work, and resume after `resets_at`. Never auto-enable extra usage. Never fall back silently to an API key.
6. **Escape hatch.** Keep the API-key backend (OS keychain). Note that Max/Team monthly API credits *can* fund Agent SDK runs via an API key, which suits always-on agents (Pro is not eligible). Re-check the legal page, the Help Center article and the SDK overview each release.
7. **Sharing later.** Every user brings their own login or key (unchanged). Branding is never "Claude Code".

## 2. Competitors: Grok Bot (SpaceXAI/xAI) and OpenAI Dots

### Grok Bot (beta launched 2026-08-11)
- **What it is:** persistent "teammate" agents. Each Bot runs on a **cloud computer** (Linux) and "can continue working 24/7". You can watch its screen and take it over. [S] https://venturebeat.com/orchestration/spacexais-grok-bot-turns-agents-into-persistent-digital-coworkers-that-can-operate-your-apps-for-120-per-month
- **Platforms:** desktop apps for macOS and Windows plus iPhone (iOS 18+). Android is "coming soon". Sources conflict on Linux desktop (VentureBeat says yes; eesel and Composio say the docs don't list it). [S] https://www.eesel.ai/blog/grok-bot-review · https://composio.dev/content/guide-to-frok-bot
- **Triggers:** scheduled routines, event triggers "where supported", a "teach a task" demo that becomes a routine, and claimed proactivity. [S]
- **Integrations:** connectors, plugins and MCP, plus **operating any website's UI** when no API exists. The user types passwords, 2FA codes and CAPTCHAs during a takeover. [S]
- **Memory:** per-Bot role, preferences and summaries. Bots learn when to ask for approval. [S]
- **Teams:** 2–6 Bots in a group chat hand off work, and a "Chief of Staff" Bot coordinates specialists. This is very close to Bench's concept. [S]
- **Pricing:** Cursor Ultra $200/mo, Cursor Premium Teams $120/seat/mo, or SuperGrok Heavy ($300/mo). No free tier. Weekly allowances, overage at token cost, **no spend cap**. No model choice (automatic router). [S]
- **Weaknesses:** all Bots on an account share one computer, browser sessions and CLI credentials, so they are **not a security boundary**. No audit view yet (transcript only). Approval rules are written in prose, and Auto Review is opt-in. No dry run. Deleting a Bot leaves sessions behind. No SOC 2 or GDPR claims, and backend storage is mandatory. Complaints about token burn ("Biggest downsides are token expenditure", HN). A swarm hit its weekly limits and stalled mid-task. Metering bugs and a waitlist. One Reddit user called it "a browser with chaos privileges". [S] eesel (a competitor; quotes not independently verified), Composio.

### OpenAI Dots (launched 2026-09-29, DevDay)
- **What it is:** a persistent agent on GPT-6 Astra that keeps working after the chat closes. Each Dot has its **own cloud Linux computer with Chrome**. Access to your local machine is optional and off by default. [S] https://techcrunch.com/2026/09/29/openai-launches-dots-its-bubbly-agentic-avatar/ · https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams
- **Platforms:** chat on web, desktop and mobile. Creating a Dot requires desktop. Also reachable via Slack and Microsoft Teams, with SMS in a US-only Pro beta and voice. [S] https://www.eesel.ai/blog/openai-dots
- **Triggers:** scheduled and recurring tasks, plus **read-only background "proactive research"** between conversations. Event triggers are not well documented. [S]
- **Integrations:** "4,000+ apps" via plugins. Can start Codex cloud tasks. [S]
- **Memory:** inherits ChatGPT memory and learns from connected apps. **Memories cannot be viewed, edited or deleted individually** (only by deleting the Dot). [S]
- **Teams:** **ChatGPT Space** holds shared Pages, files and context for people, Codex and Dots. Specialist Dots for company roles are an enterprise pilot. [S]
- **Safety:** Custom Rules (allow / ask / block), an Activity View, auto-review of consequential actions, and saved credentials used without exposing them to the model. OpenAI says injection defenses "do not eliminate" the risk. [S]
- **Pricing:** the first Dot is included in Pro $100/$200/$500 and Business Premium. Pro excludes the EEA, UK and Switzerland. Additional Dots and capacity are unpriced. Dot chats don't count against ChatGPT limits, but there is a separate "deeper work" allowance (undisclosed) and no user-set dollar cap. [S]
- **Weaknesses:** **one Dot per plan** (not a team). Opaque memory. Approvals are too frequent on routine steps. No 2FA fetch. Computer use is slower than Codex. One test logged 155 traces and about 307k tokens in a day. Demo glitches at launch. Reviewers call it "a glorified Codex session that runs 24/7". [S] https://www.eesel.ai/blog/openai-dots-review · https://www.promptadvisers.com/openai-dots-review

### Other close competitors
- **Anthropic's own stack:** Claude Cowork (desktop agent, Jan 2026; Windows in Feb; Scheduled Tasks + Projects + Dispatch in March; web and mobile with cloud runs from July). Claude Code cloud scheduled tasks with schedule, API and GitHub triggers [V, link above]. Claude Projects run parallel cloud sessions. **This is the most dangerous competitor**: same models, same subscription, and it runs in the cloud while the laptop is closed. [S] https://fast.io/resources/claude-cowork-review-2026/ · https://hatchworks.com/blog/claude/building-agents-with-claude/
- **Meta Muse** (2026-09-08, US): a consumer personal agent on iOS, Android, web and soon WhatsApp. Each user gets a cloud VM, a "Sentinel" action reviewer, and confirmation before sends and purchases. Free tier plus paid plans. Downside: it needs a lot of personal data. [S] https://www.techrepublic.com/article/news-meta-muse-ai-agent-us-launch/
- **OpenClaw** (open-source harness): the reason Anthropic tightened subscription use in April 2026. Shows the demand, and the policy risk. [S]

### What could beat Bench, and where Bench wins [I]
- **They win on:** running 24/7 in the cloud while the laptop is shut, mobile apps, operating a browser on any website, and zero setup.
- **Bench can win on:** a **real team** (Dots is one agent per plan); **true per-agent isolation** of memory and connectors (Grok Bots share credentials, and Dots memory is opaque); **glass-box visibility** (Grok has no audit view, and Dots memory can't be edited); **inspectable, editable memory as files**; **model choice per agent** (Grok has none); **no new subscription** (runs on the Claude plan you already have, versus $120–$500/mo); **local data**; open source.
- **Gap to plan for:** Bench stops when the laptop sleeps. Either say so plainly (show "agents run while Bench is open"), or later hand off to Anthropic's cloud scheduled tasks.

## 3. What users complain about in agent-team products
- **Cost and token burn.** Always-on agents and swarms burn tokens fast (Grok Bot HN; Dots: 307k tokens/day; OpenClaw: $109/day vs $6/day). Users hate **no spend cap** and **opaque allowances** (Grok, Dots). Gartner expects >40% of agentic AI projects to be cancelled by end of 2027 because of "escalating costs, unclear business value or inadequate risk controls". [S] https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027
- **Hitting limits mid-task.** Swarms stall when weekly limits run out (Composio). Claude Code limits drained in minutes by bugs or runaway subagents. [S]
- **Babysitting.** Glean's Work AI Index (June 2026, secondary coverage) found about 6.4 h/week of "botsitting" and 36% of sessions failing. Too many confirmations on routine steps (Dots). One AI strategist switched off 2 of her 4 agents because she was "spending more time babysitting them". [S] https://letsdatascience.com/news/ai-strategist-fires-half-of-her-agents-e3c79029 · https://watts.it.com/modules/the-supervision-paradox
- **Trust and safety.** Agents acting as you make you the "accountability sink". Misclassifying a send or a CRM write as "routine". Shared credentials across agents. No audit trail. Approvals can't undo actions already taken. Prompt injection is not solved. [S] eesel reviews
- **Opacity.** Memory you can't see or edit (Dots). No model choice (Grok). A green "success" status that doesn't mean the work succeeded (Anthropic's own docs warn about this for scheduled tasks). [S]/[V]
- **Setup and access friction.** Waitlists, plan lockouts, regional exclusions (EEA/UK for Dots Pro), login bugs, CAPTCHAs and 2FA that need a human. [S]

**Implications for Bench [I]:** show live and projected usage with hard caps per agent and per day; approvals that are structured (not prose) and enforced in code; an audit log of every action; editable memory; a "dry run" or preview for outward actions (send, post, write); onboarding in under 5 minutes with the existing `claude login`.
