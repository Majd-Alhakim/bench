# Spike S-1: a hook-only canary with no model turn

**Date:** 2026-10-26 · **Branch:** `spike/SP-H1` (shares SP-H1's harness) · **Code:** [`spikes/S-1/canary.mjs`](../../spikes/S-1/canary.mjs), [`spikes/SP-H1/mock-api.mjs`](../../spikes/SP-H1/mock-api.mjs) (throwaway)
**Setup:** Claude Code 2.1.310 in an isolated profile with the SP-H1 guard plugin, Windows 11, Defender on.

**Verdict: GO.** The canary drives the guard through the **real Claude Code hook path** (the real CLI, the real plugin, real PreToolUse) with **0 tokens** and gets a deny receipt every time.

## How it works
Claude Code accepts `ANTHROPIC_BASE_URL`. The canary starts a tiny loopback server that speaks the Messages API and answers the first main-loop request with one scripted `tool_use`: `Bash: git push origin main`. It answers the next request with "canary done". The canary process gets `ANTHROPIC_BASE_URL=http://127.0.0.1:<port>`, a dummy `ANTHROPIC_API_KEY` and `--no-session-persistence`, runs `claude -p` in a throwaway git repo under `%TEMP%`, and reads the deny receipt from the tool result.

## Results (20 runs)

| GO bar | Result |
|---|---|
| A deny receipt | ✅ **20 / 20** carry the guard's receipt (`PreToolUse:Bash hook error: Eucas: pushing to the default branch is off limits (receipt …)`) |
| 0 tokens | ✅ `usage` 0 in / 0 out, `total_cost_usd` 0 on every run |
| Time | p50 **0.95 s**, p95 1.06 s per run (CLI start-up included) |
| Traffic leaving the PC | None: no non-loopback host in the debug log, no unexpected path at the stand-in (with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`) |

## Notes for the design (C-1, ADR-0014)
- **Product shape:** the local canary runs the **user's own** CLI and profile (it must test the user's real plugin install), with only three things set in the canary child's env: `ANTHROPIC_BASE_URL` (loopback), a dummy key and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`. Add `--no-session-persistence`, so it never appears in the user's history.
  - Never a real key, never a credential read (ADR-0002).
  - `NO_PROXY=127.0.0.1` so a corporate proxy can't swallow it.
- **CI:** the same path removes the weekly paid model turn ADR-0014 planned as a fallback. The nightly canary can run on every CLI release at $0.
- **Caveats:**
  - An organisation's managed settings that force a login method or an `apiKeyHelper` may refuse the dummy key; then the canary reports `untested`, never `guarded`.
  - The user's other plugins' SessionStart hooks also run during the canary (side effects are theirs; time is about 1 s).
  - The stand-in must follow the Messages API's streaming shape. Keep it under a contract test, since a CLI change to the request shape would show up as `untested`.
- The UI copy can say "a test with no tokens" (D-5 resolved in favour of hook-only).
