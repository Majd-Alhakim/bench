**Isolation is also the biggest token saver:** the un-isolated agent carries ~47k tokens of the user's connectors, skills and plugins on every first turn; the isolated one carries ~2k. That's **~22× cheaper** per cold start. On a subscription, "cost" is the SDK's API-price estimate; what matters is the share of the plan window.

## Findings for the design
1. **Built-in skills and agents still appear in `init`.** Even with `settingSources: []` and `skills: []`, `init` lists Claude Code's own 22 bundled skills (e.g. `code-review`, `loop`), 3 built-in plugins (`cc-plugin-*`) and 6 built-in subagent types. None of the user's 239 skills or 10 plugins appear. They can't be used unless we grant the tool: without `Skill` or `Agent` in `tools`, the agent can't invoke them, and with `Skill` on, only the allow-listed ones are visible to the model. **Rule:** the runner always sets `tools` explicitly, and `skills` to Euca's own list.
2. **The way to give an agent skills is a local plugin** (`plugins: [{ type: "local", path }]`) plus a `skills` allow-list with `plugin:skill` names. This fits CR-005's built-in library.
3. **The plan meter is readable** through `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET()`. It's marked unstable, so wrap it behind one adapter and cover it with the M9 contract test.
4. `persistSession: false` keeps spike runs out of the user's own `claude` history. The real runner will persist sessions in Euca's home folder.
