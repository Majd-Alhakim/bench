# Spike M8: shell containment on native Windows 11 Home

**Date:** 2026-10-24 · **Branch:** `spike/g0-feasibility` · **Code:** [`spikes/m8/`](../../spikes/m8/) (throwaway)
**Setup:** a folder jail and command allow-list in [`guard.mjs`](../../spikes/m8/guard.mjs). Paths are resolved the way the OS will, following symlinks and junctions. Shell chaining, redirection and variables are refused. Every decision is traced. SDK 0.3.290, Claude Code 2.1.303, Sonnet 5.5 for the live run.

**Recommendation: GO**, enforced in a **PreToolUse hook** (finding 1).

## Findings for the design
1. **Enforce in a PreToolUse hook, not only in `canUseTool`.** Claude Code auto-allows some calls, like reading a file inside the working folder, and those never reach `canUseTool`. The hook saw every call; `canUseTool` missed the safe inside read. Claude Code did send the junction read to `canUseTool`, but the jail shouldn't depend on that. **Rule:** the hook is the jail; `canUseTool` stays as a second layer with the same guard.
2. **Claude Code's built-in Windows sandbox is not usable yet:** *"the Windows sandbox is not active on this session (feature gate off)"*. With `failIfUnavailable: true` it refuses to start, which is correct. Re-check on each Claude Code upgrade (M9); when it turns on, it adds OS-level isolation under our guard.
3. **The allow-list has to stay strict.** A string-level shell check can't see everything a program does once it runs. For example, `node script.js` can read anything the user can. So the allow-list names exact commands per agent (tests, git, build), and anything else becomes a question to you (the fallback in PRD §10). Pair it with M10: one git worktree per agent.
4. With CR-008, deletes outside git are never automatic anyway. The guard should also refuse `del`, `rm`, `Remove-Item` and `rmdir` outright, whatever the allow-list says.

## Not covered here
WSL2 or container mode (optional, later), network limits for commands, and child processes started by allowed programs. Those need the OS sandbox or WSL2, and they're in the SRS as risks.
