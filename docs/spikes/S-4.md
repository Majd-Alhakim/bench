# Spike S-4: "Open session" (find and focus the window hosting a session)

**Date:** 2026-10-26 · **Branch:** `spike/SP-ST1` (small, shares the shell PR) · **Code:** [`spikes/S-4/`](../../spikes/S-4/): `find-host.ps1` (read-only), `focus-host.ps1` (changes focus; run by hand)
**Setup:** Windows 11 Home. Read-only Win32 queries over the founder's running Claude Code processes: process tree (CIM) + `EnumWindows`. Window titles were **not** read into this report (they can name private projects); only whether one exists.

**Verdict: provisional GO with limits; the focus half is on the [manual checklist](G6-MANUAL-CHECKLIST.md).** Screen control was stopped at the founder's request, so focusing a real terminal or VS Code window waits for the founder to run `focus-host.ps1` once per host.

## What was measured (read-only)
- **The desktop app (the top host for this founder):** all **25** running CLI sessions were traced to **one** window, the Claude desktop app's. Focusing that window works with plain `SetForegroundWindow`; picking the session *inside* it can't be done from outside. So for desktop sessions: **focus the app and name the session** ("Open Claude, session: api-server").
- **Process names collide:** the desktop app's main process, its bundled CLI and the terminal CLI are all `claude.exe`. Classify by image path (`%LOCALAPPDATA%\AnthropicClaude\…` = the desktop app; `%APPDATA%\Claude\claude-code\<ver>\` = the desktop app's CLI; `~\.local\bin` or npm = a terminal CLI).
- **Windows Terminal and conhost:** the CLI's parent chain is `claude.exe < shell < WindowsTerminal.exe` (or the console belongs to `OpenConsole.exe` / `conhost.exe`, which isn't an ancestor). `find-host.ps1` handles both. WT has no public API to select a tab, so the plan is: focus the WT window and **name the tab** by the session's console title (read by attaching to its console).
- **VS Code:** the chain runs through `Code.exe`; focus the VS Code window and name the folder.

No terminal or VS Code sessions were running during the spike, so those rows are untested (manual checklist).

## GO bar
"Focus works for the top 3 hosts; names the tab otherwise." Desktop app: focus the window ✅ (one window), the session can't be picked → name it. Windows Terminal and VS Code: ⏳ manual. Focus from a background app needs foreground rights: in the product, the click on the toast or panel button gives Eucas those rights (`AllowSetForegroundWindow` / activation), so "Open session" must run inside that click handler, not later.
